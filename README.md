葵花码工具箱（微信葵花码 + 抖音圆码）
=========================================

纯 Python 实现，编码/解码算法均由逆向官方实现得到并逐位验证，不依赖任何 DLL。
抖音圆码另内置官方渲染引擎（Node + WASM），没有 Node 时自动回退纯 Python 渲染。


一、支持范围
------------

| 码制 | 生成 | 解码 | 说明 |
|------|------|------|------|
| 微信葵花码 | ✅ | ✅ | 微信小程序码的圆形变体，72 槽 × 16 环 |
| 抖音圆码（DY_CODE） | ✅ | ✅ | 极坐标环码，3/4/5 环，120 模块/环 |
| 普通方形二维码 | — | — | 不在本工具范围内 |

解码页做了自动回退：先按葵花码解，失败再按抖音码解，两种码拖进去都能认。


二、运行
--------

免安装：双击 `葵花码工具.exe`。

源码运行：
    python main.py

依赖：
    Python 3.9+   Pillow
    Node.js 18+   仅「抖音圆码 · 官方渲染引擎」需要（找不到时自动回退纯 Python 渲染，功能不减）


三、界面
--------

五个标签页：**解码 / 编码 / 抖音圆码 / HTTP 服务 / 设置**

【编码】微信葵花码
  · 输入内容 → 选尺寸 → 生成 → 保存图片
  · Logo 位置：中间（默认）/ 右下角 / 不加
  · 「选择自定义 Logo」换图，「恢复官方 Logo」回到微信官方

【抖音圆码】
  · 内容：自动提示「四环（≤38 字节）」或「五环（≤51 字节）」，超了直接标红
  · 参数：尺寸 400/500/600/800/1024、前景色、透明底、定位标记、中心播放图标（默认**关**）
  · 中心图片：`选择` / `粘贴`（读剪贴板）/ `清除`；不选则中心是纯色圆盘
  · 右上角抖音 logo：默认显示内置音符；可 `自定义` 换图、`恢复` 回内置、或取消勾选
  · 生成 → 保存 PNG / 复制图片
  · 识别：选图片解码；主界面拖图也会自动回退到抖音码

【解码】
  · 直接把图片拖进窗口（自动跳到解码页并识别）
  · 也可以「选择图片」或「从剪贴板粘贴」

【HTTP 服务】
  · 填端口 → 启动 → 用接口调用

【设置】
  · 开机自启、数据目录、运行日志


四、命令行
----------

抖音圆码：
    葵花码工具-cli.exe dy "内容" -o a.png
    葵花码工具-cli.exe dy "内容" -o a.png --size 800 --transparent
    葵花码工具-cli.exe dy "内容" -o a.png --center 头像.png --badge 徽标.png
    葵花码工具-cli.exe dy "内容" -o a.png --no-badge --logo
    葵花码工具-cli.exe dy-decode 图片.png

    --size         400 / 500 / 600（默认）/ 800 / 1024
    --color        前景色，默认 #161823
    --transparent  透明底
    --center       中心图片路径
    --badge        右上角自定义徽标路径
    --no-badge     不画右上角 logo
    --logo         画中心播放图标（默认不画）

服务与自启：
    葵花码工具.exe --serve              启动界面并同时开 HTTP 服务（默认 8686）
    葵花码工具.exe --serve --port 9000  指定端口
    葵花码工具.exe --autostart on       开机自启（含服务，加 --no-serve 则只自启界面）
    葵花码工具.exe --autostart off      关闭自启
    葵花码工具.exe --autostart status   查看状态

说明：`葵花码工具.exe` 是无控制台的 GUI 程序，`dy` / `dy-decode` 的输出会写到
`<输出文件>.txt` 和 `dy_decode.txt`；要看实时输出请用 `葵花码工具-cli.exe`（同一份代码）。


五、HTTP 接口
-------------

    方法  路径            参数 / 请求体                        返回
    GET   /encode         text, size, logo, pos                PNG
    POST  /encode         {"text","size","logo","pos"}         PNG
    POST  /decode         请求体 = 图片二进制                   JSON
    GET   /dy             text, size                            PNG   ← 抖音圆码
    POST  /dy             {"text","size"}                       PNG
    POST  /dy/decode      请求体 = 图片二进制                   JSON
    GET   /health         无                                    能力状态
    GET   /               无                                    自测页面

   （`wxsrv_pure.py` 另提供 `GET /decode?file=本地路径`，界面默认用的是 `wxsrv.py`）

示例：
    curl "http://127.0.0.1:8686/encode?text=hello" -o a.png
    curl "http://127.0.0.1:8686/dy?text=hello&size=600" -o b.png
    curl --data-binary @b.png http://127.0.0.1:8686/dy/decode
    → {"ok":true,"text":"hello","format_code":5,"ring_count":4,"mask_id":4}


六、容量与限制
--------------

微信葵花码：charset82 字符集，约 42 字符（自动选版式）。

抖音圆码：载荷按 UTF-8 原样存（QR 字节模式），容量由版式决定：

| 格式码 | 数据环 | 码字 | 码字分配 | 载荷上限 |
|--------|--------|------|----------|----------|
| 4 | 3 环 | 37 | RS(37,29)，8 纠错 | **27 字节** |
| 5 | 4 环 | 52 | RS(52,40)，12 纠错 | **38 字节**（默认） |
| 6 | 5 环 | 67 | RS(67,53)，14 纠错 | **51 字节** |

注意两点：

1. 抖音 App 里看到的链接往往更长，因为扫码后会追加归因参数，例如
   `https://v.douyin.com/5IMlPzrwees/`（33 字节，码里存的就是这个）
   `?zlink_app_id=1128&zlink_update_version_code=408018`（51 字节，客户端拼上去的）
   合起来 84 字节，但**后 51 字节不进码**。

2. 有些样式的码看着有「6 条环」，实际是：
   4 条数据环（含最外那条加粗的格式环）+ 1 条细虚线装饰环（厚度约 2.5px，数据环是 6px）
   + 1 圈定位环/徽标。承载数据的永远只有数据环，判据就是厚度和是否有意义（RS 校验）。

八、算法概要 · 微信葵花码
--------------------------

编码：
  1. 文字 → charset82 查表 → 截断 Horner → 字节
  2. 字节 → 截断 Horner(base45) → 字母数字串
  3. 位流 = 模式(4) + 长度(9) + 双符号对(11) + [单符号(6)]
  4. 终止符 + 0xEC/0x11 填充
  5. RS 纠错（GF 0x11D）
  6. 数据位按 (slot, ring) 排布 + 模板 + 掩码 + 定位符

解码：
  1. 径向扫描定圆环外缘，估算中心与比例
  2. 按 72 槽 × 16 环采样
  3. 逐掩码去掩码 + RS 综合校验（伯利坎普-梅西）
  4. 位流解析出字母数字串
  5. 候选枚举 + 正向验证还原原文

几何：72 槽（5°）× 16 环（半径 105+10k），画布 660×660
      槽角度 = (slot − 36) × 5°
      Logo 默认位：(437.63, 437.63) 110×110


九、算法概要 · 抖音圆码
------------------------

码流：
  1. payload = UTF-8 字节
  2. 位流 = 模式 0100(4) + 长度(8) + 字节 + 终止符(4) + 补零 + 0xEC/0x11 填充
  3. RS(GF 0x11D, fcr=0) 生成纠错码字（按格式码选分块）
  4. 环内字段：
       环0（最外、加粗）  15 位格式码，起点 105 位，异或 0x6492
       环1               18 位参数，起点 45 位，异或 0x25412（可关闭）
      param & 0x0F = 掩码 id（0..8）
  5. 数据位按 scramble 置换（T_EVEN/T_ODD，步长 30）写入各环
  6. 掩码谓词 mask_predicate(mask_id, w) 取反后写入
  7. 固定暗模块 (0,100)、(0,109)

解码：
  1. 定位：优先找中心暗圆盘（作品分享码），失败则假定居中 + 扫圆盘半径
  2. 由圆盘半径推各环半径（环/盘比例固定）
  3. 每环采 120 个模块，枚举 120 种旋转相位
  4. 环0 取 15 位 → 汉明距离 ≤3 → 格式码 → 环数/RS 布局
  5. 环1 取 18 位 → 参数 → 掩码 id
  6. 逆置换 + 去掩码 → 载荷码字 → RS 纠错 → 字节流
  7. 按 QR 字节模式解析出文本

几何（相对画布边长）：

| 项 | 值 |
|---|---|
| 数据环半径（由外到内） | 0.3657 / 0.3021 / 0.2681 / 0.2338 / 0.2014 |
| 模块厚度 | 0.0116（最外格式环 0.0231，约 2 倍） |
| 中心圆盘 | 4 环 0.2037，5 环 0.1829 |
| 定位环中心 / 外径 | 0.430 / 0.048（角度 45° / 135° / 225°） |
| 右上角 logo 中心 / 外径 | 0.434 / 0.056（315° 槽位，内边缘刚好在格式环之外，不压数据环） |
| 外圈装饰 | 4 段 64° 弧，半径 0.4440、宽 0.0380，0/90/180/270° 为中心 |

两族对照：

| 项目 | 微信葵花码 | 抖音圆码 |
|---|---|---|
| 每环模块 | 72（5°） | 120（3°） |
| 数据环 | 16 | 3 / 4 / 5（格式码 4/5/6） |
| 默认版式 | 多种 | RS(52,40) |
| 载荷编码 | charset82 → base45 | UTF-8 直存（QR 字节模式） |
| 位流 | 模式4 + 长度9 + 双符号11 | 模式4 + 长度8 + 字节 |
| 填充 | 0xEC / 0x11 | 0xEC / 0x11 |
| 纠错 | GF(0x11D) | GF(0x11D)，fcr=0 |
| 头部字段 | — | 环0 15 位格式码、环1 18 位参数 |
| 打乱 | — | scramble 置换 + 9 组掩码 |
| 定位 | 3 个圆环 | 3 个圆环 + 中心圆盘 |


十、校验记录
------------

抖音圆码：
  · 与官方实现逐位比对：4 环 / 5 环全部 agree = 1.000（120 个模块一个不差）
  · 生成 → 官方解码器扫回原文：四环、五环、中文、长文本、透明底、带中心图，全部通过
  · 生成 → 本工具解码：5 尺寸 × 3 载荷 × 5 选项共 **75 组，0 失败**
  · 真机样例解码：抖音分享码 33 字节短链、第三方品牌码（红花 + 音符 logo）均解出
  · 细节：加粗的格式环（0.0231）**不加圆端帽**，否则端帽会把相邻模块的缝隙连死，
    600px 下 20 个模块读错；普通环（0.0116）保留圆端帽（与官方圆角块一致）

微信葵花码：
  · 逐字节对齐官方实现，编码/解码闭环

十二、常见问题
--------------

Q：生成的抖音码用微信/支付宝扫不出来？
A：正常。抖音码只有抖音 App 的「扫一扫」能识别；微信、支付宝、系统相机的扫码器
   只认 QR 和葵花码体系。

Q：内容超过 38 字节怎么办？
A：会自动升到五环（≤51 字节）；再长就超版式上限了，先转短链。

Q：中心图会不会影响识别？
A：不会。中心圆盘不承载数据，图片会被裁成圆形并缩到圆盘的 94%，不会压到数据环。

Q：右上角那个抖音 logo 是哪来的？
A：官方「作品分享码」那个位置放的是作者头像；本工具内嵌了一枚抖音音符 logo 作为
   默认徽标（尺寸与角度按真机样图实测），也可以换成自己的图或关掉。

Q：没有装 Node 会怎样？
A：自动回退纯 Python 渲染器，功能完整，只是边缘抗锯齿与官方像素级渲染略有差异。
